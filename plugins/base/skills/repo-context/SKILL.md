# repo-context

## 目标
用最少的探索轮次，让后续每一步都站在已确认的事实上，而不是边写边猜。

## 步骤
1. **先看地图**：列顶层目录与关键清单文件（README、package.json / pyproject.toml / go.mod 等、CI 配置、贡献约定文件如 AGENTS.md / CONTRIBUTING）。读 README 和约定文件，它们优先于你的默认习惯。
2. **找入口**：定位主入口、路由/命令注册处、配置加载处。记录“要改 X 类功能，通常动哪几个文件”。
3. **检索而不是遍历**：用文本检索（符号名、错误文案、配置键）定位实现，禁止无目的逐目录翻文件。每个结论都要能指到文件路径。
4. **认既有模式**：同类功能已有的实现方式（命名、错误处理、日志、测试放法）就是本仓库的规范；新代码跟随它，不引入第二种风格。
5. **产出上下文摘要**（写入任务工作区或回复中）：
   - 结构：关键目录及职责（每处一行）
   - 入口与约定：入口文件、必须遵守的约定、测试怎么跑
   - 本次任务相关文件：路径 + 一句话说明
   - 未确认项：明确列出没查清的点，不用猜测填空

## 禁区
- 不在没读过的文件上断言其内容。
- 不把摘要写成仓库说明书：只记对当前任务有用的部分，控制在可快速读完的长度。
