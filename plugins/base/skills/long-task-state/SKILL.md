# long-task-state

## 状态文件
在任务工作区维护 `TASK-STATE.md`（没有工作区时放在项目根的 `.agent-state/` 下并告知用户位置），结构固定：

    # 目标（一句话，可验收的表述）
    ## 计划（有序步骤，checkbox）
    ## 已完成（带结果/证据，如文件路径、命令输出结论）
    ## 关键决策（决定 + 理由 + 否决的备选）
    ## 下一步（唯一明确的下一动作）
    ## 阻塞（缺什么、等谁、临时绕法）

## 纪律
1. **开始时**：先写目标和计划再动手；已有状态文件时先读它，从“下一步”恢复，不重头规划。
2. **每完成一步就更新**：勾掉计划项、把结果写进已完成。不要攒到最后一起补——中断随时可能发生。
3. **决策要留痕**：换方案、放弃一条路时，写清理由，防止下次会话重新踩一遍。
4. **状态与事实分开**：已完成只写已被验证的结果；推测写进阻塞或标注“未验证”。
5. **结束时**：若任务完成，写明最终产出位置并把“下一步”标为无；未完成则保证新会话只读这一个文件就能接上。

## 反模式
- 把状态文件写成流水账日志（只留当前真相，不留过程噪音）。
- 多个任务共用一份状态文件（一任务一份）。
